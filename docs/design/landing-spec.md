# ヒキツギ — 入口の画面の設計（R1）

対象：取扱説明書 HTML の「最初に見える画面」
前提：`visual-spec.md` の配色、文字、余白、角丸、影、バッジの決まりをそのまま使う。HTML 1 ファイル、外部への通信と読み込みなし、JavaScript なしでも全文が読める。
関係する文書：`plain-words.md`（言葉の説明。「困ったときは」の対応表を、この画面の探す処理でも使う）

---

## 0. 先に結論

### 決めたこと

1. **「はじめに」と「困ったとき」を 1 つの画面にまとめ、入口にする。** 開いた瞬間に「何が起きていますか？」の入力欄が見える。表紙は画面からなくし、印刷の 1 ページ目にだけ残す。
2. **入口は上から「入力欄 → よくある症状 → すべての症状」。** 入力欄が使えない環境（JavaScript なし）でも、よくある症状とすべての症状はただのページ内リンクなので、そのまま読める。
3. **結果のカードは「① まずこれだけ」カードそのもの。** 入口の中で唯一、暖色の枠と影を持つ。主ボタン「このページを開く」が画面でただ 1 つの暖色ボタン。
4. **① がない症状が 1 番に来たら、カードの主役を連絡先に替える。** 業者なら電話ボタンが主役、社内ならページを開くボタンが主役。手順だけある症状は「手順を開く」が主役。
5. **PC は真ん中だけで完結する。** 左の一覧は「ざっと眺める」ための補助に格下げし、真ん中に折りたたんだ「すべての症状」を持つ。右のレールは、入口では連絡先の抜粋（押せない文字）にする。
6. **写真で相談するボタンは墨の枠線ボタン。暖色にしない。** 会社の設定で出さないときは、その行ごと消え、入力欄が幅いっぱいになる。何も空かない。
7. **探す処理は端末の中だけで動く。** 題名、言い換え、言葉の説明の「困ったときは」の対応から、文字の重なりで点をつける。通信しない。

### 本人に判断してほしいこと

- A. 表紙を画面からなくしてよいか（§7-1）。動画の冒頭カットが変わる。
- B. 「よくある症状」の選び方の既定（§3-3）。自分で直せる → 確認してから → 残りを分類順、スマホ 4 件、PC 6 件。会社ごとに差し替える設定も用意する。
- C. 症状ごとの「言い換え」のデータを、根拠なしでエージェントに作らせてよいか（§6-2）。主張ではなく探すための索引なので、Verifier の照合から外す案にした。
- D. 入口の右レールを「連絡先の抜粋」にしてよいか（§4-3）。
- E. 写真で相談するボタンの会社設定の名前と既定値（§3-4）。既定は「出さない」にした。

## 1. この画面の役目と、読む人の状態

- 読むのは後任。PC が不調で、スマホを片手に、何が起きているか自分でもうまく言えない。
- だから入口は **質問を 1 つだけ** する。「何が起きていますか？」。分類を選ばせない。正しい言葉を求めない。
- 入力の結果は **その場で、やることまで** 出す。ページを開く前に「1 分でできる最初の操作」が見えれば、不安が下がる。
- うまく書けない人のために、すぐ下に **よくある症状** のボタン、さらに下に **すべての症状** の一覧を置く。入力欄が使えなくても、下に行けば必ず着く。
- 当てはまらないときは **「当てはまる症状がないとき」** に案内する。行き止まりを作らない。

### 3-2. P1 見出しと安心の一文

- 見出し：「何が起きていますか？」28px 700。`h2`。
- 安心の一文：「開いて読むだけなら、PC や機器には何も起きません。」15px `--ink-2`。今の「困ったとき」から移す。
- 今の「いま困っていることを押してください。」は使わない。入力欄があるので「押す」が合わない。

### 3-3. P2 入力欄

| 項目 | 値 |
|---|---|
| 高さ | 56px（`min-height`。文字拡大で伸びてよい） |
| 文字 | 17px、`--ink` |
| 枠 | 2px `--line-strong`、角 12px、背景 `--card` |
| フォーカス | 枠を 2px `--accent` に、外側に 3px の `--accent` の輪郭（押す場所だから暖色） |
| 左の余白 | 16px |
| 消すボタン | 右端の内側、44×44px、「×」の SVG 20px、`--ink-2`。値が空のときは出さない。読み上げ名は「入力を消す」 |
| 文字数 | 最大 60 文字 |
| 種類 | 1 行のテキスト入力。自動補完、自動大文字、スペルチェックは切る。入力モードは標準の文字 |
| 読み上げ名 | 見出し P1 と結びつける |
| 仮の文字（placeholder） | 「例：Wi-Fi が切れた、フォルダが開かない」15px `--ink-3`。これに頼らず、案内は下の文で出す |

入力欄の下の案内文（15px `--ink-2`、上 8px）：

> 正しい言葉でなくて大丈夫です。画面に出ている言葉や、見えたままを書いてください。

「よくある症状」のラベルと重ならないように、この案内はよくある症状の説明を兼ねない。

### 3-4. P3 写真で相談するボタン

- 見た目：高さ 48px、幅いっぱい、枠 2px `--ink`、文字 16px 700 `--ink`、背景 `--card`、角 12px。左にカメラの SVG 20px。**暖色は使わない。** 暖色は結果のカードの主ボタンに取っておく。
- 文言：「写真で相談する」。
- 置き場所：入力欄の案内文の下、12px 空けて。入力欄と「同じ入口の別の手段」であることが、縦に並ぶことで分かる。
- 押したあと：**未定。** この文書では見た目と場所だけ決める。何をするにしても、**HTML が画像を外へ送ることはない**（この前提は実装の制約として残す）。
- 会社の設定で出さないとき：この行と、その上の 12px の余白を **両方なくす**。入力欄の案内文の次に、32px 空けて「よくある症状」が来る。空の枠や薄いボタンを残さない。
- 設定の名前（案）：会社の設定に `landing.photo` のような 1 つの真偽値。既定は「出さない」。理由は、押したあとの動きが決まっていないボタンを既定で見せたくないから。
- JS なし：出さない（押しても何も起きないボタンを置かない）。

### 3-5. P5 よくある症状

- ラベル「よくある症状」14px 700 `--ink-2` 字間 0.04em。上 32px（写真ボタンなしのときも 32px）。
- 2 列、列間と行間 8px。各ボタンは既存の症状カードと同じ部品（`a.sym`）で、縦に題名（16px 700、2 行まで）とバッジ（15px）を並べる。目安の分数は出さない（幅が足りない）。右端の「›」も出さない。
- 最小高さ 88px、内側の余白 12px 16px。
- 件数：スマホ 4 件（2 行）。
- 選び方の既定：判定が「自分で直せる」の症状を分類順に、次に「確認してから」を分類順に、まだ足りなければ残りを分類順に。会社の設定で症状 ID の並びを指定できるようにし、本人の確認の段階で入れ替えられるようにする。
- 押すと：その症状のページを開く（一覧から押したときと同じ）。

### 3-6. P6 すべての症状

- 見出し「すべての症状」22px 700。上 48px。id は `all-symptoms`（結果なしのカードと PC の中列から飛ぶ先）。
- 直後に「判定の見かた」：14px ラベル、2×2 の凡例。バッジ 15px、説明 15px `--ink-2`。表紙からここへ移す。一覧を読む直前に意味を覚えてもらう。
- そのあとは今の「困ったとき」の一覧をそのまま置く：ジャンプ行、分類見出し、症状カード、「当てはまる症状がないとき」カード。
- 今の「困ったとき」見出し（28px）はなくす。画面の見出しは P1 ただ 1 つ。

### 4-2. 今の 3 列との関係

| 場面 | 左列 | 中列 | 右レール |
|---|---|---|---|
| 入口（今回） | 症状の一覧（補助） | 入力欄、よくある症状、畳んだすべての症状 | 連絡先の抜粋 |
| 症状ページ（既存） | 症状の一覧（現在位置つき） | 手順ページ本体 | この症状の情報、直らなかったら |

- 今の中列の「いま困っていることを押してください。」の空白は、入口そのものに置き換わる。中列が空の状態はなくなる。
- 入口から症状ページへは、既存の切り替え（JS あり：パネルの表示切り替え、JS なし：ページ内リンク）をそのまま使う。
- 症状ページの「‹ 症状の一覧に戻る」は、文言を **「‹ 最初の画面に戻る」** に変える。戻った先は入口で、**入力欄の文字と結果のカードは残っている**（パネルを隠しているだけなので、状態は消えない）。

### 4-3. 右レール（入口のとき）

- 見出し「連絡先」14px ラベル。

```
│    あれば、ダブルクリックしてください。     │
│ ┌──────────────────────────────────┐ │
│ │ ✓ 開けば、直っています。             │ │ ← ゴール行（既存の部品）
│ └──────────────────────────────────┘ │
│ ┌──────────────────────────────────┐ │

│ └──────────────────────────────────┘ │
```

- 操作は 1〜3 個。番号は丸囲み（28px、墨の枠 2px、文字 15px）。暖色は使わない。
- ゴールがない症状（first_goal が空。例：工場の Wi-Fi が切れる）はゴール行を出さない。代わりに主ボタンの下の一文を「うまくいったか、ページで確かめられます。」にする。
- 「ほかに近い症状」は 2 件まで。点が足りなければ 1 件、または区切り線ごと出さない（§6-4）。
- 題名の文字リンクと主ボタンは同じ場所へ行く。主ボタンがあるので、題名は暖色にしない（`--ink`、下線なし、押すと背景 `--card-2`）。

### 5-2. ① がなく、手順もない症状（例：複合機が故障した、不審なメールが届いた）

連絡先を主役にする。

```

│ 受付は平日9時から17時です。              │ ← 15px 副次色

│ ┃ 総務室の複合機が故障しました。          │ ← 引用（既存の部品、user-select: all）
```

- 社内（電話番号がない。総務課、社長）：電話ボタンの行をなくし、**「ページを開く」が主ボタン（暖色ベタ）** になる。「連絡する相手」に「総務課」、「伝えること」に引用を出す。
- 連絡先がない症状（fallback が空）：「連絡する相手」の塊を出さず、「ページを開く」を主ボタンにする。

### 5-3. ① がなく、手順はある症状（例：スキャンしたファイルが届かない、全社でネットがつながらない）

手順の入口を出す。手順そのものは入口に出さない。手順は分岐帯や会社の情報の表と組になっていて、切り出すと抜けが出るため。

```
│ やること                                │ ← 14px ラベル
│ NAS の空き容量を確かめて、空きがあるのに    │ ← 判定の一文 17px 500

│ │     手順を開く（3 手順）  ›          │ │ ← 主ボタン 56px 暖色ベタ
│ └──────────────────────────────────┘ │

│ ─────────────────────────────────── │
```

- 判定が「業者へ連絡」「社内で相談」で手順もある（例：全社でネットがつながらない）：§5-2 の形（電話ボタンが主役）にして、二次ボタンを「手順を開く（N 手順）」にする。電話の前にやる手順（契約番号の控えを出す）があることを、「やること」の一文で伝える。

### 5-4. 3 通りの決め方（まとめ）

## 6. 動き（状態と探す処理）

### 6-1. 状態

| 状態 | 入力欄 | P3 | P4 / P4' | P5 以下 |
|---|---|---|---|---|
| 入力前 | 空。仮の文字が見える。消すボタンなし | 出る（設定による） | 出ない | 出る |
| 入力中（1 文字以上、候補あり） | 文字。消すボタンあり | 出る | P4 が出る | 出る（位置が下がるだけ） |
| 入力中（候補なし） | 同上 | 出る | P4' が出る | 出る |
| 消したあと | 空 | 出る | 消える | 出る |
| JS なし | **P2' に置き換わる** | 出ない | 出ない | 出る |

- 結果は **入力のたびに** 更新する。決定キーや「探す」ボタンを待たない。150ms の間を置いて最後の入力だけ処理する。
- 日本語入力の変換中（未確定の文字）でも更新する。かたかなをひらがなに寄せてから比べるので、未確定でも当たる。
- 決定キー（Enter）：いちばん近い症状のページを開く。候補がなければ何もしない。
- Esc：入力を消す（消すボタンと同じ）。
- 結果のカードの領域は読み上げに「控えめに知らせる」設定（`aria-live="polite"`）。更新のたびに「近い症状：共有フォルダが見えない。ほかに 2 件。」の 1 文を読み上げ用に出す。フォーカスは動かさない。
- 入力中にページが勝手にスクロールしない。結果のカードは入力欄の直下に出るので、スマホのキーボードが出ていても上端が見える。
- 主ボタンでページを開いたあとは、そのページの先頭にスクロールする（既存の動き）。
- 切り替えの動き：結果のカードは不透明度 0→1 を 120ms。`prefers-reduced-motion: reduce` では動きなし。高さの変化にアニメーションは付けない。

### 6-2. 探す処理（端末の中だけ）

通信も外部の辞書も使わない。生成時に、AI ではないプログラムが HTML の中に **索引** を埋め込み、閲覧時の JavaScript がそれを読む。

索引の 1 件（症状ごと）：

| 欄 | 中身 | 重み | 出どころ |
|---|---|---|---|
| 題名 | 症状の題名 | 1.0 | 取扱説明書のデータ |
| 言い換え | 後任が言いそうな別の言い方。8 個まで、各 20 文字以内 | 0.9 | **エージェントが症状ごとに作るデータ（判断 C）** |
| 言葉 | その症状の「このページのことば」と、`plain-words.md` の「困ったときは」でこの症状を指している語 | 0.7 | 言葉の説明のデータ |
| 分類 | インターネット、印刷とスキャン、など | 0.5 | 取扱説明書のデータ |
| 連絡先 | この症状の連絡先の会社名 | 0.4 | 取扱説明書のデータ |

言い換えは事実の主張ではなく探すための索引なので、Verifier の照合の対象から外す案にした。ただし、AI ではない検査で **会社名、人名、電話番号、ドメイン、数字の列を含まない** ことと、許可リストの語だけであることを確かめる。

正規化（入力と索引の両方に同じ処理）：

1. 全角と半角をそろえる（NFKC）。英字は小文字に。
2. かたかなをひらがなに。
3. 空白、句読点、記号（、。！？・「」（）()）を取り除く。
4. 入力は、空白と「、」で区切って **語の列** にする（「wifi 切れる」のように 2 語で書く人のため）。区切りがなければ 1 語。

点のつけ方：

1. 語ごとに、索引の各欄との点を出す。入力の語が欄の文字列に含まれる、または欄の文字列が語に含まれるなら 1.0。そうでなければ、2 文字ずつの並び（バイグラム）の重なりの割合（Dice 係数）。語が 1 文字のときは含まれるかどうかだけで見る。
2. 欄の点に重みを掛け、欄の中で最大を取る。
3. 症状の点は、語ごとの点の平均。
4. 点の高い順に並べる。同点は一覧の並び順。

しきい値：

- いちばん近い症状として出す：点が 0.35 以上。
- 2 番目、3 番目として出す：点が 0.25 以上、かつ 1 番の 60% 以上。
- どれも 0.35 未満：結果なし（P4'）。

入力が言葉の説明の語に **そのまま一致** したとき（例：「ルーター」）は、カードの「ほかに近い症状」の下に 1 行「ことばの説明：ルーターとは？」（16px、暖色の文字リンク）を足す。

### 6-3. 結果なしのカード（P4'）

枠 1px `--line`、角 12px、背景 `--card`、内側 20px。暖色の枠は付けない（主役ではないため）。

```
┌──────────────────────────────────────┐
│ 合う症状が見つかりませんでした。            │ ← 18px 700
│ この説明書に載っていないだけかもしれません。  │ ← 17px
│ 言い方を変えるか、下の一覧から探してみて     │
│ ください。それでもなければ、社内で相談して   │
│ 大丈夫です。                            │
│ ┌──────────────────────────────────┐ │
│ │     当てはまる症状がないとき  ›       │ │ ← 主ボタン 56px 暖色ベタ → 連絡先（社内）
│ └──────────────────────────────────┘ │
│ すべての症状から探す ›                   │ ← 16px 暖色の文字リンク → #all-symptoms
└──────────────────────────────────────┘
```

- この状態では「当てはまる症状がないとき」が画面でただ 1 つの暖色ベタ。
- 「あなたの書き方が悪い」と読める文を入れない。「見つかりませんでした」と「載っていないだけかもしれません」で止める。

### 6-4. 候補の出し分け

- 1 番だけが点を超えた：「ほかに近い症状」と区切り線を出さない。
- 2 番だけ：1 件。
- 3 件以上：2 番と 3 番。4 番以下は出さない。

### 6-5. JavaScript がないとき

- `html.no-js` では P2、P3、P4 を出さない（`.js-only`）。
- 代わりに P2'（`.no-js-only`）を見出しの下に出す：

> この画面では、下の一覧から近い症状を選んでください。

  17px、`--ink`。余計な説明はしない。
- よくある症状（P5）はただのページ内リンクなので、そのまま押せる。
- すべての症状（P6）はスマホでは常に展開。PC の中列では `details` を **JS なしのとき `open` にする**（`.no-js details.all-symptoms` を開いた状態で生成し、JS ありで閉じる。JS なしで閉じたままだと、左列のない幅で一覧に着けない）。
- 症状ページはすべて縦に並んでいるので、リンクで飛ぶだけで読める（既存の保証）。

## 11. 迷った点と選んだ案

| 迷った点 | 選んだ案 | 捨てた案と理由 |
|---|---|---|
| 表紙を残すか | 画面からなくし、印刷に残す | 残す案：入口の前に 1 画面挟むと、不安な人が「困ったときは」を押すまでに 1 手増える。動画の冒頭は入口の画面でよい |
| 入力前に暖色ベタを置くか | 置かない | 「探す」ボタンを暖色にする案：入力のたびに結果が出るので、押す必要がない。押しても何も起きないボタンになる |
| 写真ボタンの色 | 墨の枠線 | 暖色の枠線：入力前に暖色がそこだけになり、「写真が主な入口」に見える |
| 写真ボタンの位置 | 入力欄の直下（PC は右隣） | よくある症状の下：文字で書けない人が、ボタンを見つける前に一覧を読み始める |
| よくある症状の件数 | スマホ 4、PC 6 | スマホ 6：結果のカードが出たとき、すべての症状が遠くなる |
| 結果のカードが出たらよくある症状を隠すか | 隠さない | 隠す：画面が動いて不安を増やす。よくある症状は暖色を持たないので、主役の邪魔をしない |
| 候補の最大数 | 1 番 + 2 件 | 5 件：選ばせる数が増えるほど、不安な人は選べなくなる |
| PC の中列に全症状を置くか | `details` で畳んで置く | 左列に任せる：中列だけで完結しない。読み上げやキーボードの経路が左列へ飛ぶ |
| 入口の右レール | 連絡先の抜粋（押せない文字） | 空にする：3 列の右が空くと、画面の 2 割が無駄になる。電話ボタンを置く：暖色が増える |
| ① がない症状の結果 | 連絡先を主役に（§5-4） | 「ページを開く」だけ：業者へ連絡の症状で、電話番号がカードにないのは遠回り |
| 言い換えの根拠 | 根拠なし、AI ではない検査だけ | 根拠を求める：聞き取りに「後任が言いそうな言い方」は出てこない。求めると索引が題名だけになり、探せない |
| 探す処理の方式 | 文字の重なり（バイグラム） | 形態素解析：外部ライブラリなしでは作れない。AI：通信が要る |
