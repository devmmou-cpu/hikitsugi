# ヒキツギ — 画面デザイン仕様（作り直し版）

対象：Built with Claude: Japan 2026 提出作品「ヒキツギ」の出力物（会社の IT 取扱説明書 HTML）
前提：PC 用は HTML 1 ファイル、スマホ用は1ファイル1症状の束（`docs/design.md` の 11/3）／外部読み込みなし／JS なしで全文可読／16px 以上・44px 以上／ライト・ダーク・印刷対応

---

## 0. 先に結論

- 一番の弱点は見た目ではなく **手順ページの情報設計**。15 手順のうち 1〜4 は「データ」、5 は「分岐」、15 は「例外」で、佐藤さんが最初に押すべき行動が見えない。ここを直さないと、どんな配色にしても「頼れる道具」には見えない。
- 2 番目は **PC がスマホの引き伸ばし** であること。審査動画の大半は PC 画面で撮ることになるので、ここが作品の第一印象を決める。
- 3 番目は **作品らしさがゼロ** なこと。Okojyo-Soft の痕跡がどこにもなく、色も意味づけされていない。
- 良い点は残す：文体（「開いて読むだけなら何も起きません」「再接続だけなのでデータは消えません」）、判定バッジという発想、接続先のコード表示、用語の「とは？」。これらは作品の中核なので、デザインはこれを引き立てる方向で作る。

## 1. 現状の批評

### 1-1. スマホ（重要な順）

1. **手順ページの構造が「やることリスト」になっていない。**
   「共有フォルダが見えません」の 15 手順は、1〜4 が接続先の表、5 が Windows 10 の分岐、6〜14 が本来の操作、15 が例外処理。チェックボックスが「Z ドライブは \\OKOJO-NAS\図面 です」に付いていて、何をチェックするのか分からない。「次はこれ」の強調が行動でない項目に付いているのが致命的。
2. **階層が平坦。** ページヘッダー（社外秘／会社名／タイトル／日付）、画面見出し、カテゴリ見出し、カード、バッジがすべて同じ「黒い太字の塊」で、視線の着地点がない。タイトル「ITの取扱説明書」（約 18px）が画面見出し「困ったとき」（約 28px）より小さく、文書としての主従が逆。
3. **判定バッジの形が揃っていない。** 「自分で直せる」「確認してから」は淡色の丸みのあるチップ、「業者へ連絡」だけ黒ベタ・角のある四角。別の部品に見えるうえ、黒ベタは「警告」に見えて、ブランドの「やさしく」と衝突する。4 種のうち「社内で相談」が一度も出てこない。
4. **差し色（茶）の意味が定まっていない。** タブの下線・手順番号の丸・「次はこれ」の枠・電話ボタンに同じ茶を使っていて、「押せる場所」と「ただの装飾」の区別がつかない。
5. **ヘッダーが毎画面 3 行を占める。** 社外秘・会社名・タイトル・日付は必要な情報だが、スマホの 1 画面目でこの 4 要素に 110px 使い、肝心の「いま困っていること」が下に押し出されている。
6. **ダークモードは「反転しただけ」。** 茶を帯びた背景（#1C1A17 系）にカードの境界が沈み、差し色の茶は暗い背景で濁る。コピーボタンが細い枠線のみで、主操作のはずなのに弱い。
7. **連絡先カードの属性 4 つ（どんな会社か／受付の時間／控えの場所／伝えること）がすべて同じ重さ。** 緊急時に必要なのは「電話番号」「受付時間」「伝えること」の 3 つで、「どんな会社か」「控えの場所」は補助。
8. **細部の粗さ。** 「ドライブ とは？」の半角スペース、「次はこれ」のラベルと本文の間隔、チェックボックスがカードの右上に浮いている、「終わった手順：0 / 15」が JS 前提の表示になっている。
9. **ブランドの不在。** Okojyo-Soft の名前も、マークも、固有の造形もない。審査員の記憶に残る要素がない。

### 1-2. PC（重要な順）

1. **スマホ画面を 640px 幅で中央に置いただけ。** 左右 30% ずつが空白で、画面の 6 割が使われていない。作品として「作り込まれていない」印象を最初の 1 秒で与える。
2. **下部タブバーが PC に残っている。** 画面全幅の固定バーが 4 項目のために 80px を占め、PC の慣習（上部ナビ／左サイドバー）と合わない。
3. **一覧と手順を同時に見られない。** 手順ページで「どの症状を見ているか」「ほかにどんな症状があるか」が消える。15 手順は PC でも 3 画面分スクロールし、接続先の表と連絡先は同時に見えない。
4. **カードの中が左に寄り、右が空く。** 640px 幅のカードに 1 行のテキストと右端の矢印だけ。目線が往復する。
5. **ヘッダーに構造がない。** 社外秘・会社名・タイトル・日付が左上に積まれているだけで、文書の「表紙」としての役目を果たしていない。パンくずもない。

### 1-3. 動画審査の観点で

3 分の動画では、1 画面あたり 3〜5 秒しか映らない。現状は 1 画面に要素が多く、文字が小さく、強調が分散している。「この画面で言いたいことは 1 つ」になるよう、画面ごとの主役（一覧なら判定バッジ、手順ページなら「まずこれだけ」カード、連絡先なら電話ボタン）を決めて、それ以外を一段落とす。

## 2. コンセプトと「作品らしさ」

### コンセプト（1〜2 行）

> **雪の上に置かれた一冊の取扱説明書。**
> 白い紙と墨の文字で落ち着いて読め、「あなたが押す場所」にだけオコジョの毛色が灯る。

### 作品らしさを出す場所（4 点に絞る）

| # | 要素 | 何をするか | 審査員が覚えるもの |
|---|---|---|---|
| A | **暖色の意味を固定する** | 差し色（毛色 #8A4E22 / ダーク #E2A66F）は「人が押す・人が動く場所」にしか使わない。電話ボタン、コピーボタン、「いまやる手順」、タブの現在位置。装飾・見出し・番号には使わない。 | 「オレンジのところを押せばいい」という一貫したルール |
| B | **「まずこれだけ」カード** | 手順ページの最上部に、1 分で済む操作を大きな 1 枚で置く。ページ内で唯一、影と暖色の枠を持つ。 | 画面を開いた瞬間に「これをやればいい」が分かる |
| C | **判定バッジ 4 色の統一システム** | 一覧でも手順ページでも PC の左列でも、同じ形・同じ 4 色で「次に誰が動くか」を示す。色＋アイコン＋文字の三重符号。 | 症状一覧を眺めるだけで会社の IT の「自分で触れる範囲」が見える |
| D | **確認の印** | 表紙と各手順ページ末尾に、名前、「確認」、確認日を入れた小さな角印風マーク（SVG）。「AI が調査して、人が確認した文書」という作品の主張を可視化する。 | 引き継ぎ文書としての信頼感、ヒキツギという名前との結びつき |

ブランド表記は控えめに：フッターに 1 行「このファイルは Okojyo-Soft のヒキツギで作られました。」と、オコジョのシルエット（白い体・黒い尾先の SVG、16px）を置く。それ以上は出さない。会社（オコジョ精工）の文書であって、Okojyo-Soft の宣伝物ではない、という立場を守る。

## 3. スマホの画面構成

幅 375px 基準。ページ左右の余白 16px。コンテンツ幅 343px。

### 3-1. 共通：ヘッダー（コンパクト版）

スクロールで消えてよい（固定しない）。高さ 56px。

```
┌──────────────────────────────────────┐
│ [社外秘] オコジョ精工 ITの取扱説明書     │  ← 1 行。社外秘は 12px 枠付き、会社名 15px、タイトル 15px 太字
│ 2026年11月5日 確認                     │  ← 14px、副次色
└──────────────────────────────────────┘
```

「〜時点の内容です」は表紙（はじめに）にだけ書き、各画面の上では「確認」の 2 文字にする。手順ページ末尾の「もとにした情報」には、調査データの時点を書く。

### 3-2. 下部タブ（4 つ）

- 高さ 64px（+ `env(safe-area-inset-bottom)`）、`position: sticky; bottom: 0`。
- 項目：困ったとき／連絡先／毎月やること／会社のIT。アイコン 24px + 文字 12px… ではなく、**文字 13px 太字** を維持（16px 未満だが、タブラベルは例外として 13px を許容。嫌なら 4 項目→アイコンなしで 16px にする）。
- 現在位置：文字とアイコンを暖色、上辺に 3px の暖色バー。非選択は副次色。
- JS なし：`<a href="#help">` などのページ内リンク。全セクションが縦に並んでいるので、リンクで飛ぶだけで成立する。
- JS あり：`html.js` 配下では非選択セクションを `display:none` にして、タブで切替。

### 3-3. 画面 1：困ったとき（症状一覧）

```
困ったとき                              ← 28px 太字
いま困っていることを押してください。     ← 17px
開いて読むだけなら、PC や機器には何も起きません。 ← 15px 副次色

インターネット                           ← 15px 太字 副次色、上 24px 下 8px
┌──────────────────────────────────────┐
│ 工場の Wi-Fi が切れます。          ›  │  ← 18px 太字、行間 1.5
│ [✓ 自分で直せる]  目安 5分            │  ← バッジ + 目安（副次色 14px）
├──────────────────────────────────────┤
│ 全社でネットがつながりません。      ›  │
│ [☎ 業者へ連絡]                        │
└──────────────────────────────────────┘
```

- カードはグループ化（現状どおり）。カード内の 1 行目は症状、2 行目はバッジ＋目安。
- 一覧の末尾に「当てはまる症状がないとき」カード（社内で相談バッジ → 連絡先の社内担当へ）。4 種目のバッジをここで必ず使う。
- グループ見出しの直前に、スクロール位置に関係なく飛べる **「ジャンプ」行** を見出しの下に 1 行置く：`インターネット · 印刷とスキャン · ファイル · メールと Teams · その他`（15px、暖色、横スクロール可）。JS 不要のページ内リンク。

### 3-4. 画面 2：手順ページ

詳細は第 5 章。縦の並び：

1. 戻るリンク（‹ 症状の一覧に戻る）
2. 症状タイトル（26px 太字）
3. 判定バッジ＋目安（1 行）
4. 「安心の一言」帯（データは消えません 等）
5. **① まずこれだけ** カード（大）
6. **② それでも直らなければ** 手順カード群
7. **③ それでもだめなら** 連絡先カード（電話＋文面コピー）
8. **この症状で使う会社の情報**（表）
9. このページのことば（用語、details）
10. 確認済の印＋出典
11. 戻るリンク

### 3-5. 画面 3：連絡先

```
連絡先                                  ← 28px
困ったときに連絡する会社です。

┌──────────────────────────────────────┐
│ クロテン通信            回線の会社     │  ← 20px 太字 + 役割ラベル 14px 副次色
│ ┌──────────────────────────────────┐ │
│ │ ☎ 03-0000-0101                   │ │  ← 56px 高、暖色、番号 22px 太字 tabular
│ └──────────────────────────────────┘ │
│ 受付  24時間                           │  ← 定義リスト 2 列（ラベル 14px 副次色 / 値 17px）
│ 伝えること                             │
│ 「会社全体でネットがつながりません。    │  ← 引用風に 1 段下げ、user-select: all
│   回線の障害か確認をお願いします。」    │
│ [文面をコピー]                         │  ← 二次ボタン
```

- 順番：社内（相談先）→ 業者。緊急度より「まず誰に言うか」の順。
- 「どんな会社か」はカード見出し右の役割ラベル（回線の会社／PC とサーバーの保守／複合機）に圧縮する。

## 4. PC の画面構成

ブレークポイント：
- `< 768px`：スマホ構成
- `768–1199px`：2 列（左：一覧 320px、右：内容）
- `≥ 1200px`：3 列（左：一覧 320px、中：内容 最大 680px、右：補助レール 300px）

上部ナビと左右の列は `position: sticky` で固定。下部タブは `display:none`。

### 4-1. 上部バー（高さ 64px、下辺 1px 罫線）

```
┌────────────────────────────────────────────────────────────────────────────┐
│ [社外秘] オコジョ精工 / ITの取扱説明書    困ったとき  連絡先  毎月やること  会社のIT   2026.11.05 確認 ◎ │
└────────────────────────────────────────────────────────────────────────────┘
```

- 左：社外秘チップ、会社名（15px 副次色）、タイトル（17px 太字）。
- 中央：4 セクションのナビ（16px、現在位置は暖色＋下線 2px）。JS なしではページ内リンク。
- 右：確認日＋角印風マーク（24px）。

### 4-2. 「困ったとき」セクション（3 列）

```
┌──────────────┬──────────────────────────────────┬──────────────────┐
│ 症状の一覧    │ 共有フォルダが見えません。          │ この症状の情報    │
│ (sticky)     │ [✓ 自分で直せる] 目安 約10分       │ (sticky)         │
│              │                                  │                  │
│ インターネット │ ┌─ ① まずこれだけ ──────────────┐ │ ドライブと接続先  │
│ ● 工場の Wi-Fi│ │ Windows キー + E → PC →        │ │ Z \\OKOJO-NAS\図面│
│ ○ 全社でネット │ │ 赤い × のドライブをダブルクリック│ │ S …スキャン       │
│ ○ Wi-Fi のパス│ │ [開けば直っています]           │ │ X …経理          │
│              │ └───────────────────────────────┘ │ Y …総務          │
│ 印刷とスキャン │                                  │                  │
│ ○ スキャンが  │ ② それでも直らなければ             │ 直らなかったら    │
│   届きません  │ 1 ……                              │ カワウソシステム  │
│ ...          │ 2 ……                              │ [☎ 03-0000-0102] │
│              │                                  │ 平日 9〜18 時     │
│              │ ③ それでもだめなら                 │                  │
│              │ ...                              │                  │
└──────────────┴──────────────────────────────────┴──────────────────┘
```

- **左列（320px）**：症状の一覧。グループ見出し（13px 太字 副次色 大文字間隔なし）＋ 各症状が 1 行（16px）。先頭にバッジを **色の点（10px 丸）＋アイコン** に縮約して表示（文字は hover/title で）。現在の症状は左に 3px の暖色バー＋背景を薄い暖色。
- **中列（最大 680px）**：手順ページ本体。第 5 章の構成そのまま。ただし「会社の情報」と「③ 連絡先」は右レールに **も** 出す（中列にも残す。印刷・2 列時のため）。
- **右レール（300px）**：「この症状の情報」＝ドライブ表、「直らなかったら」＝電話＋コピー。sticky なので手順を読みながら常に見える。
- 2 列時（768–1199）：右レールを中列の末尾に戻す（DOM 順はもともと末尾にあり、3 列時だけ `grid-area` で右へ移す）。
- JS なし：左列はページ内リンク（`#t1` など）、中列は全症状が縦に並ぶ。`:target` で現在の症状に暖色バーを付ける（`.symptom:target` と、左列は `a[href="#t1"]` の対応を CSS では取れないので、JS なしでは「現在位置」表示は中列側の `:target` のみ）。

### 4-3. 他セクション

- **連絡先**：2 列グリッド（カード幅 420px 程度）。社内相談先を先頭に 1 枚全幅。
- **毎月やること**：左に「毎週／毎月／年に 1 回」の目次、右にカード。年 1 回は月名を左に太字で揃えたタイムライン風（罫線 1 本）。
- **会社のIT**：機器カードを 2 列。「置き場所／役割／止まると」は定義リスト 2 列で横に。用語集は右レールに sticky で A–Z… ではなく出現順。

## 5. 手順ページの情報設計

### 5-1. 原則

- **手順は「人がやる操作」だけ。** データ（接続先、PC 名）と分岐条件（Windows 10）と例外（パスワード画面）は手順から出す。
- **1 手順 = 1 動作 = 1 文。** 「〜を押してください」「〜を選んでください」で終わる。確認（「開けば直っています」）は手順ではなく **ゴール表示** として別部品にする。
- チェックボックスは「やった」の記録。確認文・分岐・データには付けない。
- 会社固有の値は本文に埋め込まず、`<code>` チップで表示し、表にまとめて別枠に置く。手順側は「一覧の接続先」と指す。

### 5-2. 共有フォルダの例（15 → 8 手順＋ゴール）

```
共有フォルダが見えません。
[✓ 自分で直せる]  目安 約10分
（安心帯）つなぎ直すだけなので、データは消えません。

① まずこれだけ（1 分）                           ← 大カード
   キーボードの Windows キーを押しながら E を押し、
   左の「PC」を開く。赤い × のついたドライブを
   ダブルクリックする。
   → 開けば直っています。                          ← ゴール（緑のチェック行）
   ▸ Windows キーはどれ？（details）

② それでも直らなければ（約 10 分）                 ← 手順カード群、チェック付き
   分岐帯：Windows 10 の PC は手順が違います → 連絡先へ   ← 手順の外、黄色の帯
   1 赤い × のドライブを右クリックして「切断」を選ぶ。
   2 画面上の「…」を押して「ネットワーク ドライブの割り当て」を選ぶ。
   3 「ドライブ」の欄で、右の表の文字（Z など）を選ぶ。
   4 「フォルダー」の欄に、右の表の接続先を入力する。
      ↳ 補足：画面では「\」が「¥」で表示されることがあります。同じ意味です。
   5 「サインイン時に再接続する」にチェックを入れる。
   6 「完了」を押す。
   → 「見えなかった」フォルダーが開けば直っています。   ← ゴール
   例外帯：ユーザー名とパスワードを聞く画面が出たら、何も入力せずに閉じて、③へ。 ← 赤み帯

③ それでもだめなら
   カワウソシステムサービス   [☎ 03-0000-0102]  受付 平日 9〜18 時
   業者に送る文面：「共有フォルダをつなぎ直しても見えません。社内ネットワークの不調かもしれません。」
   [文面をコピー]

この症状で使う会社の情報                           ← 表
   PC              ドライブ  接続先
   全員            Z        \\OKOJO-NAS\図面
   総務用 OKJ-SOUMU-01  S   \\OKOJO-NAS\スキャン
   総務用 OKJ-SOUMU-01  X   \\OKOJO-NAS\経理
   総務用 OKJ-SOUMU-01  Y   \\OKOJO-NAS\総務

このページのことば（details ×N）
作成：2026年11月5日 田中 確認（更新があれば、次の行に「更新：〈日付〉〈名前〉 確認」）
もとにした情報：調査データ（2026年11月5日時点）、聞き取り、確認済みの標準手順
```

### 5-3. 見せ方のルール

| 要素 | 見せ方 |
|---|---|
| ①②③ の見出し | 22px 太字。番号は丸囲み（28px、墨の枠線 2px、文字 15px）。番号に暖色は使わない。 |
| ゴール行 | 緑チェックのアイコン＋「開けば直っています」。手順カードの外、左に 4px の緑バー。 |
| 分岐帯／例外帯 | 手順カードの外に置く帯。分岐は「確認してから」の黄系、例外は赤系（#B00020 / ダーク #FF8A80）。例外帯は手順の中で唯一赤を使う場所。 |
| 「いまやる手順」 | JS あり：最初の未チェック手順に暖色の左バー（4px）＋「いまここ」ラベル。JS なし：`.step:has(input:checked)` で済んだ手順を薄くし、`.step:not(:has(:checked))` の最初を `:first-of-type` 的に強調できないので、JS なし時は強調なし（済んだ手順が薄くなるだけで十分）。 |
| 進捗 | JS あり：「終わった手順 3 / 6」。JS なし：「手順は 6 つです」固定文。 |
| 会社の情報の表 | 手順の下（スマホ）／右レール（PC）。見出し「この症状で使う会社の情報」。`<table>` で、接続先は `<code>` チップ。 |
| 用語「とは？」 | 手順カード下部に `details` ではなくリンク（`#g-drive`）→ ページ末尾の用語 details へ飛ぶ。スペースなしで「ドライブとは？」。 |

### 6-3. 余白

4px 基準。トークン：`--s1:4 --s2:8 --s3:12 --s4:16 --s5:24 --s6:32 --s7:48`。

- ページ左右：16px（スマホ）／24px（PC）
- セクション間：48px、セクション見出し→本文：16px、グループ見出し→カード：8px
- カード内：16px（スマホ）／20px（PC）。「まずこれだけ」カードは 20px／24px
- リスト項目の縦：最小高さ 64px（タップ 44px を超える）
- 本文段落間：12px

### 6-4. 角の丸み

- カード・大ボタン：12px
- 小ボタン・入力・チェックボックス：8px（チェックは 6px）
- バッジ：999px（ピル）。4 種すべて同じピル
- コードチップ：6px
- 社外秘チップ：4px（文書の印らしさを残す）

### 6-5. 影

- 通常カード：影なし＋`1px solid var(--line)`。ライトでは `--shadow-card` を足してもよいが、基本は枠線。
- 「まずこれだけ」カードだけ `--shadow-hero`。ページ内で影を持つのはこの 1 枚だけ。
- 固定要素（下部タブ、PC 上部バー）：影ではなく 1px 罫線＋背景色 `--card`。
- ダーク：影は全廃、枠線と面の明度差で段差を出す。

## 7. 主な部品の仕様

### 7-1. 症状カード（一覧）

```html
<a class="sym" href="#t1">
  <span class="sym-title">共有フォルダが見えません。</span>
  <span class="sym-meta"><span class="badge badge-ok">…自分で直せる</span><span class="eta">目安 約10分</span></span>
  <svg class="chev">…</svg>
</a>
```

- `display:grid; grid-template-columns: 1fr 24px; gap: 4px 12px; padding: 16px; min-height: 72px; align-items:center;`
- 同グループ内は `border-top: 1px solid var(--line)` で区切り、グループ全体を 1 枚のカードに。
- hover（PC）：背景 `--card-2`。active：`transform: translateY(1px)`。
- フォーカス：`outline: 3px solid var(--accent); outline-offset: -3px;`
- PC 左列では `padding: 10px 12px; min-height: 44px;`、バッジは 10px の色丸＋アイコン 14px に縮約（`title` 属性で文字）。

### 7-2. 判定バッジ（4 種）

共通：`display:inline-flex; align-items:center; gap:6px; height:32px; padding:0 12px 0 10px; border-radius:999px; font-size:15px; font-weight:700; line-height:1;` アイコン 16px の SVG（`currentColor`）。

| 種類 | アイコン | 色 | 意味 |
|---|---|---|---|
| 自分で直せる | チェック | `--ok-*` | 佐藤さんが今やる |
| 確認してから | ！（丸囲み） | `--warn-*` | やる前に確認事項がある |
| 業者へ連絡 | 受話器 | `--call-*`（墨ベタ） | 外に電話する |
| 社内で相談 | 人 2 人 | `--ask-*` | 社内の誰かに聞く |

- 形・高さ・字の太さは 4 種で完全に同一。差は色とアイコンだけ。
- 「業者へ連絡」だけベタ塗りなのは意図的（唯一「外に出る」行動）。ただし角はピル。
- 印刷時：すべて白地＋1px 枠＋黒文字、アイコンで区別。

### 7-3. 手順カード

```html
<li class="step">
  <input type="checkbox" id="t1-s3">
  <label for="t1-s3">
    <span class="step-n">3</span>
    <span class="step-body">「ドライブ」の欄で、右の表の文字を選んでください。</span>
    <span class="step-box" aria-hidden="true"></span>
  </label>
  <p class="step-note">画面では「\」が「¥」で表示されることがありますが、同じ意味です。</p>
  <p class="step-terms"><a href="#g-drive">ドライブとは？</a></p>
</li>
```

- `label` 全体がタップ領域（`display:grid; grid-template-columns: 32px 1fr 28px; gap:12px; padding:16px; min-height: 64px; cursor:pointer;`）。
- 番号 `step-n`：32px 丸、`border:2px solid var(--ink)`、文字 15px 700、背景なし。**暖色は使わない。**
- チェック枠 `step-box`：28px、`border:2px solid var(--line-strong)`、角 6px。`:checked` で `background: var(--ok-fg); border-color: var(--ok-fg)` ＋ 白のチェック SVG（`mask` か背景 `data:` SVG）。
- 済み：`.step:has(:checked)` → 本文 `color: var(--ink-3)`、番号枠も `--ink-3`。打ち消し線は使わない（読み返すため）。
- いまここ（JS 付与 `.is-current`）：`box-shadow: inset 4px 0 0 var(--accent); background: var(--accent-soft);` 番号の上に 12px ラベル「いまここ」を暖色で。
- 隣接カード間 8px。カードは `border:1px solid var(--line); border-radius:12px; background: var(--card)`。
- `step-note`：15px、`--ink-2`、左に 32+12px のインデント。
- `step-terms`：15px、リンクは暖色・下線 1px 実線（点線はやめる）。

### 7-4. 「まずこれだけ」カード

```html
<section class="first">
  <p class="first-kicker">① まずこれだけ <span class="eta">1分</span></p>
  <p class="first-body">キーボードの <kbd>Windows</kbd> キーを押しながら <kbd>E</kbd> を押し、左の「PC」を開く。赤い × のついたドライブをダブルクリックする。</p>
  <p class="goal">開けば直っています。</p>
  <details class="term"><summary>Windows キーはどれ？</summary>…</details>
</section>
```

- `padding: 20px; border: 2px solid var(--accent); border-radius: 12px; background: var(--card); box-shadow: var(--shadow-hero);`
- kicker 15px 700 暖色。本文 19px 500 行間 1.7。
- `kbd`：`font: inherit; font-size: 17px; padding: 0 8px; border:1px solid var(--line-strong); border-bottom-width: 2px; border-radius: 6px; background: var(--card-2);`
- `goal`：`display:flex; gap:8px; padding: 12px 16px; margin-top: 16px; background: var(--ok-bg); color: var(--ok-fg); border-radius: 8px; font-weight: 700;` 先頭に 20px チェック SVG。
- ページ内で唯一の「暖色の枠＋影」。他のカードに同じ枠を使わない。

### 7-5. 連絡先カード

- `padding:20px; border:1px solid var(--line); border-radius:12px;`
- 1 行目：会社名 20px 700 ＋ 右に役割 14px `--ink-2`（`display:flex; justify-content:space-between; align-items:baseline`）。
- 2 行目：電話ボタン（7-6）。
- 3 行目：定義リスト `dl` を `grid-template-columns: 6em 1fr; row-gap: 8px;`。ラベル `--ink-2` 15px、値 17px。
- 「伝えること」の値は `blockquote.say`：`padding: 12px 16px; border-left: 4px solid var(--line-strong); background: var(--card-2); border-radius: 0 8px 8px 0; user-select: all;`
- 補助情報（契約番号の控え）は `details` で畳む。

### 7-6. 電話ボタン（主操作）

```html
<a class="btn btn-call" href="tel:0300000102">
  <svg>受話器</svg><span class="btn-label">電話をかける</span><span class="num">03-0000-0102</span>
</a>
```

- `display:flex; align-items:center; justify-content:center; gap:10px; min-height:56px; padding: 0 20px; border-radius:12px; background: var(--accent); color: var(--accent-ink); font-weight:700; text-decoration:none;`
- ラベル 16px、番号 22px tabular。
- hover：`background: var(--accent-strong)`（ダークは明るい方へ）。active：`transform: translateY(1px)`。
- PC では `tel:` が無効な環境もあるので、番号を `user-select: all` にし、横に「番号をコピー」（二次ボタン）を JS ありのときだけ表示。

### 7-7. コピーボタン（二次操作）

- `min-height:48px; padding: 0 20px; border:2px solid var(--accent); color: var(--accent); background: transparent; border-radius: 12px; font-weight:700; font-size:16px;`
- JS なし：`display:none`（ボタンの代わりに引用ブロックが `user-select:all` で一括選択できる）。`html.js .btn-copy{display:inline-flex}`。
- 押下後 2 秒：ラベルを「コピーしました」に変え、`background: var(--ok-bg); color: var(--ok-fg); border-color: transparent;`。

### 7-8. 用語の説明

```html
<details class="term" id="g-drive">
  <summary>ドライブとは？</summary>
  <p>パソコンの中の「引き出し」の名前です。Z や S のように 1 文字で呼びます。</p>
</details>
```

- `summary`：`min-height:48px; padding: 0 16px; display:flex; align-items:center; justify-content:space-between; font-weight:700; cursor:pointer; list-style:none;` 右に 20px の「＋」SVG、`[open]` で「−」に（`details[open] summary svg` で切替、回転ではなく差し替え）。
- 本文 `padding: 0 16px 16px; color: var(--ink-2);`
- `scroll-margin-top: 80px`（PC 上部バー分）。手順からのリンクで飛んできたとき、`:target` に `open` は CSS では付けられないので、`details.term:target{ border-color: var(--accent) }` で場所を示し、JS ありなら `open` を付与。
- 用語を複数まとめるときは 1 枚のカードに `details` を縦に並べ、区切り 1px。

### 7-9. 安心帯／分岐帯／例外帯

安心帯の文は、調査か聞き取りで裏づけられる事実か、聞き取りにある決まりだけを書く。「大丈夫です」のような保証の言い切りは書かない（`docs/design.md` の 11/4）。

- 共通：`padding: 12px 16px; border-radius: 8px; display:flex; gap: 10px; font-size: 16px;` 先頭に 20px アイコン。
- 安心帯：`background: var(--card-2); color: var(--ink);` アイコン：盾。
- 分岐帯：`background: var(--warn-bg); color: var(--warn-fg);` アイコン：！
- 例外帯：`background: var(--danger-bg); color: var(--danger-fg);` アイコン：×。手順の中で赤はここだけ。

## 9. JavaScript なしでも成り立つ動きと手触り

## 10. 審査動画向けの補足と、効果の測り方

### 動画で見せる順（提案）
1. 表紙（はじめに）を 3 秒 → 「確認済」の印と凡例が映る（注記：今の実装では、開いた直後は「困ったとき」の画面で、表紙はフッターのリンクから開きます）
2. PC 3 列の「困ったとき」。左列をスクロールして 4 色のバッジが並ぶ様子
3. 「共有フォルダ」を開く → 「まずこれだけ」カードが影付きで出る（ここが山場）
4. スマホに切替、チェックを 2 つ入れて「いまここ」が動く
5. 「それでもだめなら」→ 電話ボタンと「文面をコピー」→「コピーしました」
6. OneDrive プレビュー（JS なし）で同じファイルが全文読めるカット（技術的主張）

### 指標（作品評価・改善用）
- **初回到達**：IT 未経験者 3 人に「共有フォルダが見えない」状況を渡し、「まずこれだけ」を実行開始するまでの秒数（目標 20 秒以内）。
- **バッジ理解**：凡例を見せたあと一覧だけを見せ、「自分で触っていい症状はどれか」を当てられる率（目標 100%）。
- **JS なし可読**：iOS の OneDrive プレビューで、手順ページ 1 本を最後まで読めるか（Yes/No）。
- **コントラスト**：全文字色の組み合わせが 4.5:1 以上（上表）。実装後に自動チェック（axe か Lighthouse）で 0 件。
- **タップ領域**：44px 未満の操作部品 0 件（Lighthouse の tap targets）。

### 却下した案
- **オコジョのイラストを大きく出す**：会社の内部文書に個人開発のキャラクターが前面に出ると、佐藤さんの会社の文書に見えなくなる。フッターの 16px に留める。
- **バッジを色だけで区別**：色覚多様性と印刷で破綻。アイコン必須。
- **「次はこれ」を JS なしでも最初の未チェックに出す**：CSS だけでは「最初の未チェック」を選べないため、JS なし時は出さない方が一貫する。
- **ダークモードの茶系背景**：暖色が濁る。ダークは無彩に寄せ、暖色は明るい毛色（#E2A66F）に振る。
