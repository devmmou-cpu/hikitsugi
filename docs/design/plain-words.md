# ヒキツギ — 言葉の説明の書き方（R1）

対象：取扱説明書の「このページのことば」「ことばの説明」に出る、1 語ごとの説明文
前提：読むのは IT 未経験の後任。不安な状態で、手順の途中に出てきた語を調べに来る。
関係する文書：`landing-spec.md`（「困ったときは」の対応を、入口の探す処理の索引に使う）、`visual-spec.md` §7-8（表示の部品）

> **この文書の扱い（11/4）：** 「一言で」「たとえ」を承認済みの辞書から引く案（§0 の4、§5 の案 1）は実装していません。本人の判断（`docs/design.md` の 11/3、「辞書の承認の流れは作らない」）で、Editor が書き、字数、電話番号、アドレス、認証情報、退職者名をプログラムで止めます。人の承認はなく、Verifier の照合の対象でもありません（README の限界）。手順ページは一言と「くわしく」のリンクだけで、4段の全部は「会社のIT」に1回だけ出します（§7 と違います）。文の決まり（§3、§4）は Editor のプロンプトに入れました。

---

## 0. 先に結論

### 決めたこと

1. **1 語は 4 段で書く。** 一言で ／ たとえ ／ この会社では ／ 困ったときは。見出しの文言は固定し、順番も変えない。
2. **「一言で」と「たとえ」には、ほかの専門用語を 1 つも入れない。** 使ってよい語は §3 の「そのまま使ってよい語」だけ。「この会社では」には 2 語まで、「〜とは？」のリンクか、直後のかっこの言い換えを付けて使える。
3. **「この会社では」だけが根拠を持つ。** 文ごとに聞き取りか調査の ID を添える。記録にないことは書かない。「記録がありません」と書くのは、取扱説明書に同じ文がすでにあるときだけ。
4. **「一言で」と「たとえ」は、本人が承認した辞書から引く。** 手順部品と同じ仕組みで、辞書の ID を根拠にする。辞書にない語は、その 2 段を出さず、「この会社では」と「困ったときは」だけ出す。
5. **「困ったときは」は必ず行き先で終わる。** 症状ページがなければ「当てはまる症状がないとき」へ。行き止まりの語を作らない。

### 本人に判断してほしいこと

- A. 一般の説明の根拠を「承認済みの辞書」にする案（§5 の案 1）でよいか。辞書の置き場所と承認の手順が要る。**→ 作らない（本人の判断、11/3）。**
- B. §6 の 10 語の「一言で」「たとえ」は、承認前の下書き。このまま辞書の最初の 10 件にしてよいか。**→ 辞書を作らないので、見本のまま。**
- C. 「この会社では」に「記録がありません」の文を残すか（§4-3）。残す案にした。**→ 残している。本人の明示の判断の記録はない。**
- D. たとえの題材を事務所の物に限る決まり（§4-2）でよいか。会社によっては工場や店の物のほうが近いかもしれない。**→ Editor のプロンプトは「事務所や家にある物」。本人の明示の判断の記録はない。**

## 1. いまの作りと、変えること

| | いま | これから |
|---|---|---|
| データ | 語と、説明の文章 1 つ | 語と、4 段。一言で（辞書の ID）、たとえ（辞書の ID）、この会社では（文と根拠 ID の組の列）、困ったときは（症状 ID の列） |
| 中身 | 「この会社で何を指すか」だけ | 一般の意味 → たとえ → この会社の事実 → 行き先 |
| 根拠 | 文章 1 つに聞き取りか調査の ID | この会社では：聞き取りか調査の ID。一言で・たとえ：辞書の ID。困ったときは：症状 ID（根拠は不要。存在を検査する） |
| 表示 | `details` の中に段落 1 つ | `details` の中に 4 段。見出し 14px ラベル、本文 17px。困ったときは、各行 48px のリンク |

いまの「説明の文章 1 つ」は、そのまま「この会社では」の最初の文に移せる。

## 2. 4 段の役目と書き方

| 段 | 役目 | 長さの目安 | 文の数 | 根拠 |
|---|---|---|---|---|
| **一言で** | その語が「何の仲間か」を 1 文で言う | 30 字まで | 1 文 | 辞書の ID |
| **たとえ** | 身の回りの物 1 つに置き換える | 60 字まで | 1〜2 文 | 辞書の ID |
| **この会社では** | どこにあり、何に使い、触ってよいか | 120 字まで | 2〜4 文 | 文ごとに INT か INV の ID |
| **困ったときは** | 症状ページへの行き先 | — | 1〜3 件 | 症状 ID |

### 2-1. 一言で

- 必ず「〜する機器です」「〜のためのソフトです」「〜の仕組みです」「〜の名前です」「〜の場所です」「〜のサービスです」「〜の作業です」「〜の控えです」のどれかで終える。仲間の語はこの 8 つから選ぶ。
- 何をするか（働き）を書く。何でできているか、どう動くかは書かない。
- 英字の略語の正式名称を書かない（「NAS は Network Attached Storage の略で」は禁止）。読者には役に立たず、知らない語が 3 つ増える。
- 例：「設計図を描くソフトです。」「Wi-Fi の電波を出す機器です。」

### 2-2. たとえ

- 題材は、事務所や家にある物 1 つ。玄関、書庫、キャビネット、金庫、表札、配電盤、厨房、警備員、スピーカー、製図板、コピー、合鍵、郵便受け、内線電話、倉庫、など。
- 1 つの説明に、たとえは 1 つだけ。2 つ並べると、どちらで覚えればよいか分からなくなる。
- 書き出しは「〜です。」で言い切る（「〜のようなものです」は弱く、「〜と思ってください」は命令に聞こえる）。2 文目で、たとえと IT の対応を 1 点だけ補う。
- たとえの中に IT の語を戻さない。「サーバーはクラウドの…」のような循環を作らない。
- 子ども向けの言い回し（「魔法の」「おうち」など）は使わない。読者は大人で、仕事中。
- 例：「事務所の共用の書庫です。だれの机でもなく部屋に 1 つあり、みんなが書類をしまいます。」

### 2-3. この会社では

- 書く順番を固定する：**①どこにあるか／何を指すか → ②何に使っているか → ③触ってよいか、やってはいけないこと**。この順なら、読者は「場所を見に行く → 何が止まるか分かる → 触る前に止まる」の順で読める。
- 文ごとに根拠の ID を添える。1 文に複数の事実を入れない。
- 記録にないことは書かない。推測や一般論で埋めない。
- 「〜の記録はありません。社内で相談してください。」は、取扱説明書の本文に同じ内容の文（STM）がすでにあるときだけ、その STM と同じ根拠 ID で書く。新しく「ない」と判断して書かない。
- 固有の名前（会社名、機器の名前、PC の名前、Wi-Fi の名前、システムの名前）は、そのまま書いてよい。説明は要らない。
- 専門用語は 2 語まで。使うときは「〜とは？」のリンクにするか、直後にかっこで言い換えを付ける。
- 数字は記録どおりに書く（「10 秒」「毎週金曜」「5 つ」）。「しばらく」「いくつか」に丸めない。
- パスワードや認証情報は書かない。書いてよいのは「控えの保管場所」だけ。

### 2-4. 困ったときは

- 形式：「症状の題名」をそのまま書き、症状 ID を添えたリンク。1〜3 件。関係の深い順。
- 症状ページがない語：固定の 1 文を書く。

  > この語で困ったときのページは、この説明書にありません。当てはまらないときは「当てはまる症状がないとき」から相談してください。

  末尾に「当てはまる症状がないとき」へのリンクを置く。
- 関係の深さの決め方：その語がページの題名にある → 手順や ① にある → 会社の情報の表にある → 機器の説明にある、の順。
- この対応は、入口の探す処理（`landing-spec.md` §6-2）の「言葉」の欄にも使う。読者が「ルーター」とだけ書いても、「全社でネットがつながらない」に着く。

## 3. ほかの専門用語を使わないための決まり

### 3-1. そのまま使ってよい語

次の語は説明なしで使える。IT 未経験でも、日常や仕事で聞く語に限る。この表にない語は、すべて「専門用語」として扱う。

| 種類 | 語 |
|---|---|
| 機器 | PC、パソコン、スマホ、画面、キーボード、マウス、電源、電源ボタン、ケーブル、コンセント、プリンター、複合機、コピー機 |
| 操作 | 押す、開く、閉じる、入れる、抜く、差す、選ぶ、クリック、ダブルクリック、右クリック、入力する、再起動（電源を入れ直すこと） |
| 仕事の道具 | メール、インターネット、ネット、Wi-Fi、ファイル、フォルダ、ソフト、アプリ、パスワード、印刷、スキャン、写真、電話、サイト |
| 製品名 | Windows、Microsoft 365、Teams、OneDrive、Outlook、Excel、PowerShell、BitLocker |
| 仲間の語 | 機器、ソフト、仕組み、名前、場所、サービス、作業、控え、設定、更新、契約、保守 |
| 会社の物 | 事務所、工場、総務課、総務室、書庫、棚、柱、天井、机 |

### 3-2. 使う前の検査

1. 書いた文を、語に分けて眺める。
2. §3-1 にない語が、一言で・たとえにあれば **書き直す**。例外なし。
3. この会社ではにあれば、その語が言葉の説明に **登録されているか** 見る。登録されていれば「〜とは？」のリンクか、かっこの言い換えを付ける。登録されていなければ、書き直すか、新しく語を登録する。
4. 3 語目が出たら、文を減らす。
5. この検査は AI ではないプログラムで機械的にできる（語の許可リストと、登録済みの語の一覧を突き合わせる）。Verifier の前に走らせる。

### 3-3. 言い換えの例

| 使わない | 言い換え |
|---|---|
| ストレージ、ディスク | 記録する部品、ためておく場所 |
| ネットワーク | 社内のつながり、ネット |
| デバイス | 機器 |
| クラウド | インターネットの向こう側のサービス |
| アカウント | 使う人ごとの登録 |
| ライセンス | 使う権利 |
| サインイン、ログイン | 使い始める操作、自分の名前とパスワードを入れること |
| 初期化 | 設定を全部消して、買ったときの状態に戻すこと |
| 大型更新、フィーチャーアップデート | Windows の大きな更新 |
| リース | 借りて使っている |
| スポット（有償） | 1 回ごとにお金を払って頼む作業 |
| 管理画面 | 設定を変えるための画面 |

## 4. 文体と、書いてはいけないこと

### 4-1. 文体

- です・ます。1 文は 35 字まで。読点は 1 文に 2 つまで。
- 主語は「この機器は」「この会社では」。「あなたは」「後任は」は書かない。
- 否定で始めない。「〜ではありません」より「〜です」。やってはいけないことは「〜しないでください」と動詞で止め、理由を 1 文足す。
- 数字は半角、単位は全角の日本語（10 秒、5 つ、2 台）。
- 語の表記は取扱説明書の本文と揃える（「無線 AP」「外付け USB」「共有フォルダ」）。

### 4-2. 書いてはいけないこと

| 禁止 | 理由 |
|---|---|
| 実在の製品名、メーカー名、型番（許可された 8 つを除く） | 架空のルール。調査データの「架空メーカーA」のような表記もここでは書かない |
| 英字の略語の正式名称 | 知らない語が増えるだけ |
| 仕組みの内側の説明（「〜という方式で」「〜プロトコルで」） | 読者が使うのは働きだけ |
| 「簡単です」「誰でもできます」「ご存じのとおり」 | できなかったときに自分を責める |
| 「〜だと思います」「おそらく」 | 根拠のない推測。記録にないなら書かない |
| 退職する担当者の名前を、相談先として | 連絡先にしない決まり。確認者として角印に出るのは別 |
| パスワード、認証情報、それらしい文字列 | 書いてよいのは保管場所だけ |
| たとえを 2 つ以上 | 覚える像が割れる |
| 「この会社では」に一般論を混ぜる | 根拠が付けられない。一般の話は「一言で」へ |
| 「困ったときは」を空にする | 行き止まりを作らない |

### 4-3. 「記録がありません」の扱い（判断 C）

「置き場所の記録はありません。社内で相談してください。」のような文は、読者が探し回らずに済むので役に立つ。ただし「ない」ことを新しく判断して書くと、根拠のない文になる。そこで、**取扱説明書の本文に同じ文がすでにあるときだけ**、その文の根拠 ID を借りて書く。本文になければ書かない。

## 5. 根拠のない一般の説明を、どう確かめるか

「一言で」と「たとえ」は、この会社の調査にも聞き取りにも出てこない。いまの作りでは文章にすべて根拠が要るので、何かを根拠にしなければならない。4 つの案を比べる。

| 案 | 仕組み | 良い点 | 弱い点 |
|---|---|---|---|
| **1. 承認済みの辞書** | 手順部品（`procedures.json`）と同じように、語ごとの「一言で」「たとえ」を本人が承認した辞書に置く。辞書の各項目に ID（例：WRD-001）を付け、文章はその ID を根拠に持つ。Verifier は、文章が辞書の文と一致するかを照合する | 人が 1 度確認した文だけが出る。会社が変わっても同じ文が使え、品質が揃う。Verifier の仕組みを変えずに済む | 辞書にない語は 2 段が出ない。語が増えるたびに承認の手間がかかる |
| 2. Verifier に別の基準で判定させる | 一般の説明には根拠を求めず、代わりに「§3 の語だけか」「一般論の範囲か」「誤りがないか」を AI が判定する | 語の数に上限がない | AI が書いた文を AI が確かめるだけで、人が見ていない。「誤りがない」の判定は AI の知識頼みで、保証にならない |
| 3. 聞き取りで本人に確認する | 生成した 2 段を、聞き取りの最後に田中さんに見せ、承認を INT の記録にする。根拠は INT の ID | いまの根拠の仕組みそのまま | 田中さんは IT の専門家であって、平易な文の専門家ではない。語が 30 を超えると負担が大きく、形だけの承認になる |
| 4. 1 と 3 の組み合わせ | 辞書にある語は 1。ない語はエージェントが下書きし、本人の確認の段階で承認してもらい、承認した文を辞書に足す。次の会社からは 1 で引ける | 初回だけ手間で、回を重ねると辞書が育つ | 承認の手順を 2 か所（辞書と確認の段階）に持つ |

**おすすめは案 1 で、育て方として案 4 を取る。** 理由は次のとおり。

- この作品の主張は「AI が調べ、人が確認した文書」。一般の説明だけ人の確認を抜くと、主張が崩れる。
- 手順部品で同じ仕組みがすでに動いている。辞書は 2 つ目の部品集として同じ扱いにできる（文面の変更と承認は本人の確認を受けたときだけ）。
- §3-2 の機械的な語の検査は、辞書への登録前に走らせる。AI の判定ではなく許可リストの突き合わせなので、保証として説明できる。
- 辞書にない語は、「この会社では」と「困ったときは」だけを出す。2 段が欠けても、読者には「会社の事実」と「行き先」が残る。「準備中」のような文は出さない。

実装に関わる決め事（コードは書かない）：

- 辞書の置き場所は `plugin/library/` の下に、手順部品と並べる。項目は、語、一言で、たとえ、状態（下書き／承認済み）、承認日。
- 文章データの根拠の欄に、INT、INV、LIB に加えて辞書の ID を書けるようにする。
- Verifier は、辞書の ID を根拠に持つ文章を、辞書の文との一致で照合する（手順部品の LIB と同じ）。
- 同じ語でも「この会社では」は会社ごとに違う。辞書が持つのは 2 段だけ。

## 6. 見本：オコジョ精工の 10 語

根拠は `review-input/okojo/` の聞き取り（INT）と調査（INV）の ID。「一言で」「たとえ」は辞書に入れる前の下書き（判断 B）。症状 ID と題名は `manual-final.json` のもの。

### 6-1. ルーター

**一言で** 会社の中のパソコンを、インターネットにつなぐ機器です。

**たとえ** 会社の玄関です。外との出入りは、ぜんぶここを通ります。

**この会社では**
- UTM と 1 台にまとまった機器を、借りて使っています。（INT-007、INT-009）〔UTMとは？〕
- 事務所のサーバーラック（機器をまとめて置く棚）にあります。（INT-007、INT-009）
- 「初期化」はしないでください。設定が消えて、全社のネットが止まります。（INT-007、INT-009）
- 保守はカワウソシステムサービスです。（INT-005、INT-009）

**困ったときは**
- 全社でネットがつながらない（T5）

### 6-2. UTM

**一言で** 外からの危ない通信を見張って止める機器です。

**たとえ** 玄関に立つ警備員です。入ってくる人と荷物を見て、怪しいものを止めます。

**この会社では**
- ルーターと 1 台にまとまった機器を、借りて使っています。（INT-007、INT-009）〔ルーターとは？〕
- 事務所のサーバーラック（機器をまとめて置く棚）にあります。（INT-007、INT-009）
- 「初期化」はしないでください。設定が消えて、全社のネットが止まります。（INT-007、INT-009）
- 保守はカワウソシステムサービスです。（INT-005、INT-009）

**困ったときは**
- 全社でネットがつながらない（T5）

### 6-3. NAS

**一言で** みんなで使うファイルをためておく、専用の箱です。

**たとえ** 事務所の共用の書庫です。だれの机でもなく部屋に 1 つあり、みんなが書類をしまいます。

**この会社では**
- 事務所のサーバーラック（機器をまとめて置く棚）にあります。（INT-003、INT-009）
- 中に、総務、経理、営業、図面、スキャンの 5 つの共有フォルダがあります。（INT-004）〔共有フォルダとは？〕
- ディスク（中の記録する部品）の交換は自分でせず、社長に相談します。（INT-004）

**困ったときは**
- 共有フォルダが見えない（T1）
- NAS のディスクの交換が必要そう（T10）
- 停電のあと NAS やサーバーが起動していない（T9）

### 6-4. 無線 AP

**一言で** Wi-Fi の電波を出す機器です。

**たとえ** 館内放送のスピーカーです。1 台で届く範囲が決まっていて、部屋ごとに置きます。

**この会社では**
- 2 台あります。事務所の天井と、工場の柱に 1 台ずつです。（INT-007）
- Wi-Fi の名前は、事務所が OKOJO-OFFICE、工場が OKOJO-FACTORY です。（INT-011）
- 工場の AP は、電源を抜いて 10 秒待って差し直せば、自分で再起動してよいです。（INT-007）

**困ったときは**
- 工場の Wi-Fi が切れる（T4）

### 6-5. CAD

**一言で** 設計図を描くソフトです。

**たとえ** 製図板と定規の代わりです。紙ではなく画面に図面を描きます。

**この会社では**

- Windows の大きな更新を進めないでください。（INT-008）
- ソフトの更新は毎年 6 月です。（INT-013）

**困ったときは**
- この語で困ったときのページは、この説明書にありません。当てはまらないときは「当てはまる症状がないとき」から相談してください。

### 6-6. サーバー

**一言で** みんなで使う仕組みを動かしている、専用のパソコンです。

**たとえ** 店の厨房です。注文は各席から出しますが、作る場所は 1 つで、止まると全席に料理が来ません。

**この会社では**
- 生産管理システムが動いている機器が 1 台あります。（INT-009）
- 置き場所の記録はありません。社内で相談してください。（INT-009。本文の STM-057 と同じ）
- 勝手に再起動しないでください。困ったらイイズナソフトに相談します。（INT-009）

**困ったときは**
- 生産管理システムが使えない（T11）

### 6-7. 共有フォルダ

**一言で** 会社のみんなで同じファイルを見られる、置き場所です。

**たとえ** 大事な書類のコピーを、別の金庫にも入れておくことです。元が燃えても、コピーが残ります。

**この会社では**

### 6-10. Microsoft 365

**一言で** 会社のメールや Excel などを使うための、契約しているサービスです。
