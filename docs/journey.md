# 開発の記録

日付ごとに「問題 → 打った手 → 数字の変化」を書きます。数字はすべて `eval/results/` の記録からで、**架空の会社と模擬の田中さんによる模擬評価**です。保留の2社（ラーテル商事、ケナガ印刷）では、まだ評価していません。

## 11/2

### Verifier の検出率
- **問題：** 誤りを見つける役割が機能するかが、作品の中心です。全部を疑うだけで点が上がらないよう、誤りとよく似た正しい記述を混ぜた評価セットで測る必要がありました。
- **打った手：** Verifier の初版を作り、オコジョ精工で測定しました。誤りの種類が1件合わなかったので調べると、正解データの S-05 の分類の誤りでした。本人の確認を受けて、理由を書いた単独のコミットで直しました（`09a833d`）。
- **数字の変化：**
  - 誤り10件の検出：10件（初回から）
  - 正しい記述の誤検出：0件（初回から）
  - 種類の一致：9件 → 10件（正解データの修正による）
  - その後の調整用3社の21回の実行で、検出10件、誤検出0件が続きました。
- **読み方：** 1社10件なので、1件の差が10ポイントになります。調整に使った会社の結果で、最後の確認ではありません。

### Writer の手順が1行だった件
- **問題：** 通しの評価で、共有フォルダのページの手順が「ネットワークドライブを再接続してください」の1行でした。Verifier は合格しましたが、IT 未経験の人には実行できません。正しいことと、使えることは別でした。
- **打った手：** 次の「手順部品」を入れました。
- **数字の変化：** 共有フォルダの手順 1手順 → 11手順（オコジョ精工、`20261102T071043` → `20261102T075154`）。

### 手順部品の導入
- **問題：** 一般知識で手順を補わせると正しさを保証できず、補わせないと IT 未経験の人に使えません。
- **打った手：** PC の標準操作を、本人が確認した部品にしました（`88f3842`）。文面はプログラムが組み立て、未承認の部品があれば取扱説明書を作りません。Verifier は、部品にも根拠にもない操作を「根拠なし」にします。
- **数字の変化：** 部品を使った文章 0件 → 17件（オコジョ精工）。

### 聞き取りの網羅率
- **問題：** 質問を使い切っても聞いていない項目が残っていました（未質問 2〜4件）。Interviewer が聞き直しに質問を使っていたためです。
- **打った手：** すべての空白を1回ずつ聞き終えるまで、聞き直しも終了もしないようにしました。聞いていない項目が残っていれば、プログラムが終了を止めます（`6c948ed`）。
- **数字の変化：** 必須40項目のうちの網羅と、未質問の項目。

| 時点 | オコジョ精工 | クズリ運輸 | キノドテン建設 |
|---|---|---|---|
| 修正前（未質問） | 35（2） | 35（2） | 31（4） |
| 修正後の1回目（未質問） | 36（0） | 35（0） | 37（0） |
| 修正後の2回目（未質問） | 37（0） | 37（0） | 33（0）、37（0） |

未質問はなくなりました。網羅は実行ごとに揺れ、キノドテン建設の33は目標の85%（34項目）に届いていません。この修正の副作用は、11/3 の「質問数が 20問から減った件」に書きました。

## 11/3

### 手順ページの作り直しと、Writer をページ単位にした件
- **問題：** 手順に事実、条件、確認が混ざり、最初に押す場所が分かりませんでした（共有フォルダは15手順のうち、本来の操作は一部でした）。画面の仕様を別に作って確かめたところ、これが一番の弱点でした。3部構成に直すと、全体を1回で書く構造化出力が API の上限を超えました。入れ子にしても超えました。
- **打った手：** ① まずこれだけ、② それでも直らなければ、③ それでもだめなら の形にし、ゴール、分岐、例外を手順から分けました。部品の文面は本人の承認を受けて変えました。Writer は共通部分に1回、手順ページ1つに1回呼ぶ形にしました。差し戻しは指摘のあった部分だけを書き直し、Verifier には変わった文章だけをかけ直します（`4d3188a`）。
- **数字の変化：**

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 共有フォルダの手順（オコジョ精工） | 15手順 | ① 3つ ＋ ② 6手順 |
| Writer の費用（オコジョ精工） | $0.64 | $0.71（1.1倍） |
| Writer の時間（オコジョ精工） | 約200〜320秒 | 157秒 |
| 通しの費用（1社） | $2.16〜2.24 | $1.57〜1.93 |
| 2回目の検証の対象（クズリ運輸） | 全文 | 2文 |

### 前任者の確認
- **問題：** 画面の案に「手順は人が確認したものだけ載せています」とありましたが、人が確認しているのは部品だけで、全文を照合しているのは AI でした。読む人には、人が全文を確認したように見えます。
- **打った手：** 前任者がページごとに「このままでよい／直す」を選ぶ工程を足しました。直す内容は聞き取りの記録にして、そのページだけを書き直し、検証し直します。全ページが済むまでは「下書き（前任者の確認前）」の帯を出し、確認の印を出しません（`4d3188a`）。
- **数字の変化：** 実際の前任者では、まだ測っていません。評価では、模擬の田中さんが全ページを「このままでよい」にする設定で進めます。

### 今日の push の件とフック
- **問題：** テストが1件失敗した状態のコミット（`4d3188a`）を push しました。テストの結果を表示しただけで、失敗で止まる形にせず、コミットと push をつないでいたためです。次のコミット（`fc10684`）で直しました。機能の問題ではなく、案内の文を変えたときにテストの期待を直していなかっただけでしたが、「push の前にテストを通す」という約束を、人の注意に頼っていたことが原因です。
- **打った手：** Claude Code のフックを2つ入れました。`git push` の前に `npm test` を実行し、失敗したら止めます。取扱説明書の HTML を書き出したあとに、パスワードらしい文字列と、架空の形式以外の電話番号、ドメインを検査し、見つかれば止めます。
- **数字の変化：** 同じ形のコマンド（失敗を見ずに push までつないだもの）を、フックが止めることをテストで確かめました。

### 退職する担当者を連絡先にしていた件
- **問題：** クズリ運輸で「怪しいメールを開かずに、田中さんへ転送してもらってください。」のように、退職する本人を連絡先にする文が残っていました。聞き取りどおりなので Verifier も通しますが、説明書を読むころには連絡できません。
- **打った手：** Writer に、本文でも本人を連絡先、転送先、相談先、報告先にせず、社内の相談先の先頭に置き換えるよう指示しました。置き換え先がなければ「記録がありません。社内で相談してください」と書きます。Verifier の結果には、AI の判断によらず文字列の照合を上書きし、当たれば「危険」にします。
- **数字の変化：**

| 会社 | 修正前の最終版で照合に当たる文 | 修正後（1回目の検証、最終版） |
|---|---|---|
| オコジョ精工 | 0件 | 0件、0件 |
| クズリ運輸 | 3件 | 0件、0件 |
| キノドテン建設 | 0件 | 0件、0件 |

3社とも合格し、1社の費用は $1.53〜2.08 でした。Writer への指示の段階で直ったので、照合が止めた文は今回の3社ではありません。照合そのものが働くことは、テストで確かめています。

### 質問数が 20問から減った件
- **問題：** 通しの評価の質問数が、20問から 14〜19問に減っていました。
- **原因：** 11/2 の修正（`6c948ed`）です。それまでは聞き直しで20問を使い切り、聞いていない項目が残っていました。修正後は空白を1回ずつ聞くので、質問数はほぼ Gap Finder が作った空白の数（13〜19）になり、聞き直しは0〜3問です。Interviewer のプロンプトはこの時点から変えていません。
- **数字：**

| | 質問数 | 聞き直し | 未質問 | 「分からない」「あとで」 | 網羅（40項目） |
|---|---|---|---|---|---|
| 修正前（3回） | 20 | 3〜6 | 2〜4 | 1〜3 | 31〜35 |
| 修正後（7回） | 14〜19 | 0〜3 | 0 | 0（1回だけ 3） | 33〜37 |

- **読み方：** 網羅は下がっていません。前任者の負担は減りました。一方で、1〜6問が余ったまま、3〜7項目が埋まらずに終わっています。聞き直しの決まりはあっても、ほとんど働いていません。
- **もう1つの差：** 「分からない」「あとで」がほぼ0件になりました。1問で多くの項目を聞くようになり、模擬の田中さんの回答の作り方（回答のある事実が1つでもあれば、それだけを返す）では、「分からない」が表に出にくいためです。実際の前任者とは差が出るかもしれません。
- **未対応：** 直すかどうかは本人の判断待ちです。

## 既知の差
正解データは変えず、差として記録します。

- **キノドテン建設の「ネットが全部つながらない」：** 正解は「連絡（クロテン通信）」です。出力は実行によって変わり、「ルーターを再起動して、直らなければクロテン通信に電話」という「自分で直せる」（`20261102T224611`）や「確認してから」（`20261102T234454`）のページになることがあります。前の実行では「業者へ連絡」でした。再起動の手順は聞き取りに根拠があり、Verifier は合格しています。後任が最終的にクロテン通信へ連絡する点は同じですが、判定は一致しません。
