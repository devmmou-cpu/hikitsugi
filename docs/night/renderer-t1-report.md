## 自分で決めたこと
`CLAUDE.md` は仕様にない判断を `docs/design.md` の「決定事項」に残す約束ですが、今回の指示では変更できるファイルに入っていません。ここに書くので、問題なければ決定事項へ移してください。

| 決定 | 理由 |
|---|---|
| `routines` か `devices` に中身があれば、止める（終了コード 1） | 初版では表示しないので、黙って捨てないため。次の段階で表示を作るときに外す |
| どの画面からも参照されない記述があれば、止める | 記述が読めなくなることを防ぐため |
| 記述、連絡先、手順ページの ID の重複も止める | 参照先や HTML の id が曖昧になるため |
| 電話番号が `+`、数字、`-` だけの形のときだけ電話リンクにする。それ以外は文字で見せる | 不正な値から数字だけを拾うと、間違った番号にかかるため |
| 認証情報の検査は採点器より少し広くした（`パスコード`、`が`、語と値の間の空白、全角の英数字） | 表示は外に出る前の最後の関門なので、誤って止める方を選ぶ。止めるときに値は表示しない |
| 用語を、最初に出てくる手順の下にも置く（ページ内で1回だけ）。全用語は「会社のIT」にある | 手順の途中で意味を確かめられるようにするため |
| 用語は HTML では開いた状態にし、プログラムが閉じる | JavaScript のないプレビューや印刷でも全文を読むため |
| 指示にない「チェックをすべて外す」ボタンを足した | 保存があると、次に同じ症状で開いたときに全部チェック済みで表示されるため |
| 手順ページの「直らなかったら」に受付時間と伝えることも出す | 電話する前に、連絡先のタブへ移らずに済むため。根拠の一文の計算にも含める |
| 下部のタブは `position: sticky` にする | 流れの中に場所を持つので、文字が大きくなっても内容に重ならないため |
| タブの切り替えはアドレスの `#` で行う | 端末の「戻る」がそのまま使えるため |
| 固定の文言に「データは消えません」のような事実を書かない | 検証を通らない文章を画面に足さないため。安心の言葉は記述だけから出す |
| 根拠は ID を出さず、一文にまとめる | 後任には ID の意味が分からないため |
| 出力先に書き込めないとき、入力と出力が同じファイルのときは終了コード 2 | 約束にない部分。入力ではなく引数の誤りとして扱い、入力の上書きも防ぐ |

## 朝に見てほしい点
実機のスマホか、ブラウザーの幅 375px で `night-logs/manual-t1.html` を開いて確かめてください。

### 動作
1. **タブ：** 4つのタブで画面が切り替わり、選択中のタブが太字と上の線で分かるか。切り替えると画面の先頭に戻るか
2. **手順ページ：** 一覧から開き、「困ったとき」のタブが選択されたままか。端末の「戻る」と「症状の一覧に戻る」で一覧に戻るか
3. **チェック：** 文字を押しても切り替わるか。再読み込みや開き直しで残るか。「チェックをすべて外す」で消えるか
4. **コピー：** 「文面をコピーする」を押すと「✓ コピーしました」に変わり、約4秒で戻るか。貼り付けた文が画面と同じか。特に `file://` で開いたときと、ファイルアプリのプレビューで失敗しないか（失敗時は長押しを案内する）
5. **電話：** 「電話をかける」で 03-0000-0102 が発信画面に入るか
6. **用語：** 最初は閉じていて、押すと開くか

### 見た目
7. **下部のタブ：** 長い手順をスクロールしても下に固定され、最後まで読んでも内容に重ならないか。画面下のホームバーと重ならないか
8. **タブの文字：** 16px の4語が 375px に収まるか。「毎月やること」が不自然に折り返さないか（幅の狭い 320px でも）
9. **長い接続先：** `\\OKOJO-NAS\図面` が横にはみ出さないか
10. **ダークモード：** 見にくい色がないか。チェックボックスの見え方を含む
11. **用語の印：** 開閉の三角が二重に出たり、消えたりしないか
12. **全体の印象：** 落ち着いていて、次にすることが一目で分かるか。これはテストでは測れない。一覧のバッジや枠線が多すぎないかも見てください

### JavaScript なし、印刷
13. **JavaScript なし：** ブラウザーの設定で切るか、OneDrive のプレビューで開き、全文が上から読めるか。コピーボタンとチェック解除のボタンが出ないか
14. **印刷：** プレビューで、タブとボタンが消え、全タブの全文が黒い文字で出るか。ダークモードの端末からも試す。用語の説明も出るか

## 知っておいてほしいこと
- **「確認済み」は Verifier の結果を見ていません。** 記述の根拠 ID の種類から文を作るだけです。入力に検証結果が入らないので、Verifier に合格したものだけを表示プログラムに渡す流れで守る必要があります
- **根拠の日付は `as_of` です。** 形式に調査日の項目がないので、「調査データ（2026年11月20日時点）」の日付は `as_of` をそのまま使っています
- **認証情報の検査には誤検出と見逃しがあります。** 検査は「パスワードは」の直後の半角4文字以上を見ます（実行で確かめたのは合格テストの2例だけで、以下は正規表現の定義から読んだ動きです）
  - 誤検出：「パスワードは Excel のファイルに保管」のような保管場所の文でも止まる。採点器の正規表現も同じ形で、同じように当たる
  - 見逃し：3文字以下の値、日本語の値、語と値が離れた書き方。主な守りは Verifier です
- **「毎月やること」は空です。** T1 の範囲なので「まだこの説明書に入っていません」と出します。動画や提出の前に、この表示でよいか見てください
