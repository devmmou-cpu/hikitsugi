## Gap Finder の形式の問題（原因と、直した結果）
**起きたこと（`frames.log`）：** Gap Finder は 57 秒で `gaps.json` を保存しましたが、`check-gaps` が拒否しました。主のエージェントはスキーマと検査のコードを読み、「項目の名前が違っているだけ」と判断して、ファイルを手で書き換えず担当に直させました。直したあとは検査に通り、必須項目40件のうち調査データで分かったのは1件、残りは18件の空白にまとめられました。遅れは 31 秒です。エラーの全文は画面で折りたたまれ、1回目のファイルも上書きされたので、残っていません。

**原因：** 項目の名前を伝えている場所がありません。
- `plugin/agents/gap-finder.md` の出力の欄は「`coverage` と `gaps` を返す」とだけで、中の項目の名前がありません。
- `SKILL.md` の依頼の文も `coverage` と `gaps` の名前だけです。
- `check-gaps` は `gaps.schema.json` で検査するので、次の名前と値でないと止まります。`coverage`：`item`、`state`（`filled`、`partial`、`gap`）、`evidence`。`gaps`：`id`、`items`、`why`、`priority`（`high`、`mid`、`low`）、`question_hint`。

**評価で見えなかった理由：** 評価のスクリプトは、API の `output_config` に出力の形を渡します（`eval/lib/adapters/live.mjs`）。プラグインの担当はファイルに自由に書くので、名前を推測します。Writer の形式の失敗も同じ構造です。

**直し方（11/4、本人の判断。エージェントのプロンプトは変えていません）：** `hikitsugi init` が `hikitsugi-work/gaps-format.json` に形を書き出し、`SKILL.md` の依頼で「この形で保存してください」と伝えます。形は `gaps.schema.json` から作るので、検査とずれません。`schema_version` と `company` は `check-gaps` が付けるので含めません。作業フォルダの中で完結するので、権限の確認に左右されません。

**実物で確かめた結果：** gap-finder の段階だけを1回動かしました（`claude -p`、auto mode、Max プランの枠で API の費用なし）。
