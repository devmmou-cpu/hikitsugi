## Gap Finder の形式の問題（原因と直し方の案。直すのは明日）
- **原因：** エージェントの指示の出力の欄に、項目の名前（`coverage` の `item`、`state`、`evidence`、`gaps` の `id`、`items`、`why`、`priority`、`question_hint`）が書いてありません。評価のスクリプトは API に出力の形を渡すので間違えませんが、プラグインでは形を渡していないので、名前を推測します。評価の通しでこの問題が見えなかった理由です。Writer の形式の失敗も同じ原因です。
- **直し方の案（プロンプトを変えない）：** `SKILL.md` の依頼の文に「`${CLAUDE_PLUGIN_ROOT}/schemas/gaps.schema.json` のとおりの形で保存してください」と足します。Writer は `writer-task` の出力に形を入れます。
- **あわせて：** `status` が検査の合否を見ずに進むので、検査に合格した印を残し、印がなければ先へ進まないようにします。

## 本人の判断が要るもの
業者に伝える文は、ご指定の型のとおりに組まれ、Verifier も通っていますが、読むと不自然な例がありました。
- **T5（スキャンしたファイルが NAS に届かない）：** イタチ事務機（複合機の業者）への文に「機器の場所：事務所のサーバーラック」が入ります。題名の NAS の場所ですが、複合機の場所に読めます。
- **T8（不審なメールを受け取った）：** 総務課への文が「説明書の手順「不審なメールは開かずに、総務課に知らせてください」は試しました。直りません。」になります。操作ではない① に型が合っていません。

**おすすめ：** 機器の場所は、連絡先が扱う機器に限る情報がないので、**社内で相談のページと、題名の機器と連絡先が結びつかないページでは出さない**のは判定が難しいです。簡単な案は、(a) 「試しました。直りません。」の行は、① が手順部品のときだけ出す、(b) 機器の場所は「業者へ連絡」の判定のページだけ出す、の2つです。T5 と T8 はどちらも消えます。

もう1点、T11 の説明書に「NAS の電源ボタンを押す」とありますが、「止まっているときだけ」の条件が聞き取りにありません（主のエージェントの指摘）。回答例の文が足りないためで、README の限界の「停電のページ」に近い話です。
