## 通せなかったテストと、その理由
失敗するのは `test/renderer-visual.acceptance.test.mjs:348`「実際の画面（375px、1024px、1440px）で…」だけです。

`scripts/screenshots.mjs` の 261 行目は、ページの中で動く文字列なのに、`id` が埋め込まれていません。

```js
// 今（ページの中に id という変数がないので、768px 以上で必ず ReferenceError になる）
const beside = innerWidth >= 768 && id.startsWith('symptom-');
// 直し方
const beside = innerWidth >= 768 && ${JSON.stringify(id)}.startsWith('symptom-');
```

このため、1024px と 1440px では、どんな画面でも「ほかの画面が undefined 個見えています」と出ます。2幅 × 2テーマ × 18画面で、ちょうど 72 件です。スマホの幅では `&&` の手前で止まるので出ません。

**しなかったこと**
- `scripts/` は変更していません。テストも弱めていません
- ページに `window.id` を定義すれば検査は通りますが、検査のためだけのコードを製品に入れることになるので、入れていません

**裏づけ**
`night-logs/screens-patched.test.mjs` は、スクリプトを読み込み、この1か所だけを置き換えた写しを作って動かします。結果は「画面の検査：問題なし」でした。ただし、これは写しでの結果で、公式の検査の合格ではありません。直したあとの `npm test` は実行できていないので、次を確かめてください。

```bash
npm test
node scripts/screenshots.mjs night-logs/manual-full.html night-logs/screenshots
```

**約束から外れたこと**
`CLAUDE.md` には「コミット前に `npm test` を通す」とありますが、上の 1 件が失敗したまま、作業用ブランチに 3 回コミットしました。作業の指示がコミットを求めており、この不具合は私の側では解消できないためです。push はしていません。

## 見直しの回ごとに見つけて直したこと
毎回、主役が1つか、暖色が押す場所だけかも確かめました。

### 1回目
- 凡例のバッジが `grid` の中で `inline-flex` でなくなっていたので、親を普通のブロックにした
- 「受付　受付は24時間です。」と言葉が重なっていたので、見出しをやめて時計の印と文だけにした
- 連絡先の電話とコピーの並びを直し、「契約番号の控えの場所」をカードの底にそろえた
- PC の表紙で、上部バーと表紙に同じ題名が出ていたので、表紙では上部をナビだけにした
- 凡例の説明が長く折り返していたので短くした
- PC の一覧の左端、フッターの並び、右の列の位置を上部バーの両端にそろえた
- オコジョを3案描き、160px と 16px で見比べて、横向きの案を選んだ

### 2回目
- 操作のあとの画面を見るために、作業用のテストを追加した
- 表の行の線が二重になっていたので直した
- 下書き、チェック後、JavaScript なしの PC の画面を確かめた

### 3回目
- 「ダブルクリックしてくださ／い。」のように行末に1文字残るので、`text-wrap: pretty` と文節での折り返しを足した
- 768px の幅で、長い名前のときに上部バーの中身がはみ出したので、バーの高さを固定し、長い名前は省略するようにした
- 768px の表で「ドラ／イブ」と見出しが割れたので、普通の表にするのは 1024px 以上からにした
- 印刷に「いまここ」が残っていたので消し、一覧のバッジは文字まで出すようにした
- PC で開いている症状が一覧の外に隠れないようにした

### 4回目
- 右の列の電話が塗りつぶしで、本文の電話と主役が2つになっていたので、枠だけにした
- 「まずこれだけ」の番号が本文と近すぎる大きさだったので、少し小さくした
- 768px で題名が「ITの取扱説…」と切れたので、題名を優先して幅を配った

最後に、スマホと PC のライトとダーク（はじめに、困ったとき、共有フォルダ、手順のないページ、連絡先、毎月やること、会社のIT）と、タブレットを見ました。手順のないページは T1 です。

## 仕様と違えたところ
依頼の表にあった読み替えは、すべてそのとおりにしました。それ以外は次のとおりです。

| 箇所 | したこと | 理由 |
|---|---|---|
| 8-1 の角印 40px、4-1 の 24px | 表紙とページ末の角印は 64px。上部バーは文字のない 24px の印と、文字の「田中 確認 2026年11月5日」 | 文字を 14px 以上にすると 40px に収まらないため |
| 9 のチェック欄 1px | 28px の本物のチェック欄を透明にして枠に重ねた | 撮影の検査が 24px 以上を求めるため。手順の input も label の中に入れた（テストの約束） |
| 7-3 のチェックの SVG | `mask` や `data:` を使わず、インライン SVG を重ねた | テストが CSS の `url(` を禁じているため |
| 7-5 の「受付」の定義リスト | 時計の印と文だけ | 文が「受付は」で始まり、言葉が重なるため |
| 3-5 の「伝えること」のコピー | 連絡先のタブにはコピーを付けない | 「〜と伝えてください」という指示の文で、そのまま送る文面ではないため。手順ページの文面にはコピーがある |
| 4-2 の右の列の電話 | 枠だけのボタン | 画面の主役を1つにするため |
| 4 の表 | 普通の表にするのは 1024px 以上。それ未満は行を積む | 768px で見出しが割れたため |
| 9 の `.symptom:target h2` の暖色 | 使わない | 見出しに暖色を使わないという 2-A と矛盾するため |
| 8-1 の「前任の情シス」 | 「前任の担当者」 | IT の知識がなくても分かる言葉にするため |
